Game UI is one package, `@gameui/ui`, with separate entry points so a game loads only the layers it uses.

| Import                    | Use it for                                                                 | Loads React |
| ------------------------- | -------------------------------------------------------------------------- | ----------- |
| `@gameui/ui/react`        | Screen UI components such as Button, Panel, and Modal                      | Yes         |
| `@gameui/ui/themes.css`   | Token values, the three starting themes, and base styles                   | No          |
| `@gameui/ui/styles.css`   | Precompiled component styles for `@gameui/ui/react`                        | No          |
| `@gameui/ui/tailwind.css` | Tailwind CSS v4 mapping from utilities to tokens                           | No          |
| `@gameui/ui`              | Token names and helpers, and type-only world UI contracts for any renderer | No          |
| `@gameui/ui/input`        | Keyboard ownership between the game and focused HUD controls               | No          |

A game with React screen UI uses `@gameui/ui/react` plus the stylesheets. A game that draws everything in its own renderer, such as a canvas or three.js game without React, can use `@gameui/ui` and the theme CSS alone.

## Install

```bash
pnpm add @gameui/ui react react-dom
# A game without React screen UI only needs:
pnpm add @gameui/ui
```

React 19 is an optional peer dependency: required for `@gameui/ui/react`, unused by everything else. Without React installed, pnpm may warn that Base UI, which the components use internally, is missing its React peer; nothing outside `@gameui/ui/react` loads it. The package is ESM-only and ships TypeScript declarations. Use a bundler such as Vite, with `"moduleResolution": "bundler"` (or `node16`/`nodenext`) in `tsconfig.json`.

:::note[Developing alongside a game]
To try unreleased changes in a game, point the dependency at a local checkout, for example `"@gameui/ui": "link:../game-ui/packages/ui"`, and switch back to a version range afterwards. A linked checkout resolves to `dist`, so run `vp run @gameui/ui#build` after changes. `examples/consumer` in the repository installs a packed tarball instead, verified by `vp run verify-consumer`.
:::

### Tested versions

The consumer fixture builds and type checks against React and react-dom 19.3, TypeScript 5.9 with `skipLibCheck: false`, Vite 7.3, and Tailwind CSS 4.3, on Node 24. Other versions within the peer ranges are expected to work but are not tested. See [Compatibility and limitations](/getting-started/compatibility/) for browsers and known limitations.

## Import styles

Framework CSS lives in the `game-ui` cascade layer. Declare its position once, after resets and before utilities, then import the stylesheets.

With Tailwind CSS v4:

```css title="src/styles.css"
@layer theme, base, game-ui, components, utilities;

@import "tailwindcss";
@import "@gameui/ui/themes.css";
@import "@gameui/ui/styles.css";
@import "@gameui/ui/tailwind.css";

/* Your game styles and token overrides */
```

Without Tailwind:

```css title="src/styles.css"
@import "@gameui/ui/themes.css";
@import "@gameui/ui/styles.css";

/* Your game styles and token overrides */
```

Component styles are precompiled, so your Tailwind setup does not need to scan Game UI packages. The layer order keeps Tailwind's Preflight reset from overriding components while letting utilities you pass through `className`, and all of your unlayered CSS, take precedence. If you use another layered reset or framework, list its layers before `game-ui`.

## Select a theme

Set `data-game-theme` to `arcade`, `tactical`, or `playful` on the element that contains your game UI, usually the root:

```html
<html data-game-theme="arcade"></html>
```

A theme applies to everything inside the element, so different regions can use different themes. Modals render in a portal but still use the theme of the region they were opened from. See [Theming](/themes/) for what each theme is designed for.

## Override tokens

Your game's identity comes from overriding `--game-*` custom properties, not from editing components. Put overrides after the framework imports, scoped to the theme root or any region:

```css title="src/styles.css"
[data-game-theme="arcade"] {
  --game-primary: #7cf29a;
  --game-primary-contrast: #062611;
  --game-primary-text: #7cf29a;
  --game-radius-md: 0;
}
```

Framework styles are layered, so these win without higher specificity. When you change a colour, also set its `-contrast` and `-text` partners. [Theming](/themes/#tokens) lists every token.

## Render components

```tsx
import { Button, Panel, ProgressBar } from "@gameui/ui/react";

export function PauseMenu({ health, onResume }: { health: number; onResume: () => void }) {
  return (
    <Panel title="Paused" variant="raised">
      <ProgressBar label="Health" value={health} showValue />
      <Button onClick={onResume}>Resume</Button>
    </Panel>
  );
}
```

Components are controlled: they render the values you pass and report requests through callbacks. Keep your game loop, match rules, and state store in your game. [Components](/components/) documents each one.
