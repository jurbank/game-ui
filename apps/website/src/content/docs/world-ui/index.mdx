`@game-ui/world-ui` exports TypeScript contracts for **FloatingLabel**, **Nameplate**, and **HealthBar**: plain-data descriptions of UI attached to an entity or world position. They introduce no renderer, DOM dependency, React component, store, or update loop.

```ts
import type { HealthBar } from "@game-ui/world-ui";

const health: HealthBar<"2d"> = {
  kind: "health-bar",
  id: "health:pilot-7",
  anchor: { kind: "entity", dimension: "2d", entityId: "pilot-7" },
  offset: { space: "screen", x: 0, y: -24 },
  label: "Pilot health",
  value: 42,
  max: 100,
  tone: "warning",
};
```

Add the workspace package to your game alongside the screen/theme packages you need. Use `import type`; no world UI runtime needs to enter your game bundle. Typed descriptors are checked during development. Serialized data still needs game-owned validation at its input boundary; no JSON Schema is shipped.

## What is available

| Artifact                                            | Status                                                  |
| --------------------------------------------------- | ------------------------------------------------------- |
| [Specifications and types](/world-ui/contracts/)    | Shared public contract                                  |
| [Canvas game and React bindings](/world-ui/canvas/) | Working game-owned reference example                    |
| [3D integration recipe](/world-ui/3d-recipe/)       | Guidance; no tested 3D renderer or engine support claim |
| [React components](/components/)                    | Shipped screen UI                                       |

Your game owns render objects, entity resolution, projection, visibility, animation, updates, batching, pooling, and disposal. Use stable descriptors and native objects; update content when state changes and read spatial data directly in your game loop. Do not allocate descriptors, parse schemas, or resolve CSS values every frame.

## Connect world and screen UI

| World concept | Related screen UI                                                               | Shared data                            |
| ------------- | ------------------------------------------------------------------------------- | -------------------------------------- |
| HealthBar     | [ProgressBar](/components/progress-bar/)                                        | Value, maximum, and game-selected tone |
| Nameplate     | [PlayerList](/components/player-list/) or [Scoreboard](/components/scoreboard/) | Identity, name, and status             |
| FloatingLabel | Contextual text in [Panel](/components/panel/)                                  | Text and semantic role                 |

Both layers observe game-owned values and send actions to the game. They may render differently. World styling comes from a game-owned presentation mapping; CSS variables cannot automatically style a native renderer. See [state and presentation integration](/world-ui/integration/).
