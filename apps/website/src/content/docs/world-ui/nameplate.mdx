A character's identity in the world: name, an optional short status, and whether the player has selected them. Nameplate is a **contract**: `@gameui/ui` defines its data, and your renderer draws it.

## When to use

- Names above players, allies, NPCs, or units.
- Short state tied to that character: "Ready", "Down", "AFK".
- Showing which character is selected.

## When not to use

- Ranked or tabular data: use [Scoreboard](/components/scoreboard/) in screen UI.
- Rosters: use [PlayerList](/components/player-list/).
- Health: pair the nameplate with a [HealthBar](/world-ui/health-bar/) on the same anchor.
- Text about a place or object: use [FloatingLabel](/world-ui/floating-label/).

## Usage

```ts
import type { Nameplate } from "@gameui/ui";

const nameplate: Nameplate<"3d"> = {
  kind: "nameplate",
  id: `name:${player.id}`,
  name: player.displayName,
  status: player.health === 0 ? "Down" : undefined,
  selected: player.id === selectedId,
  anchor: {
    kind: "entity",
    dimension: "3d",
    entityId: player.id,
    localOffset: { x: 0, y: 1.8, z: 0 },
  },
  offset: { space: "screen", x: 0, y: -12 },
  occlusion: "hide", // only if your renderer supports it
};
```

## Configuration

| Field      | Type          | Default  | Meaning                                                       |
| ---------- | ------------- | -------- | ------------------------------------------------------------- |
| `kind`     | `"nameplate"` | required | Discriminates the descriptor.                                 |
| `name`     | `string`      | required | Plain display name.                                           |
| `status`   | `string`      | none     | Short plain-text state. Omitted shows no status.              |
| `selected` | `boolean`     | `false`  | Whether to draw a selection cue that does not rely on colour. |

Plus the shared fields: `id`, `anchor`, `offset`, `tone`, `visible`, `missingAnchor`, `lifetimeMs`, and the optional capabilities `occlusion` and `maxDistance`. [Shared configuration](/world-ui/contracts/#shared-configuration) defines their defaults and units.

Don't infer team, rank, or status from the anchor's entity id. Put everything the nameplate shows in its fields.

`name` and `status` are plain text a player may have written, so filter them where the name is set, not where the plate is drawn: see [Filtering player text](/patterns/text-filtering/). Store the clean string in game state and let the nameplate and the [PlayerList](/components/player-list/) read the same one.

## Tones

Tones colour the text with `--game-text` (default) or `--game-{primary,success,warning,danger}-text`. The game chooses what each tone means, for example `primary` for allies and `danger` for enemies or downed players. The reference game draws selection as a `◆` prefix with a `--game-primary` ring around the marker, on a `--game-panel` backing.

## Accessibility

- Give selection a shape or text cue, not only a colour change.
- World text is invisible to assistive technology. Provide the same identities and status in screen UI, such as a [PlayerList](/components/player-list/), and make selection possible from there with keyboard controls.
- Long names need a layout policy in your renderer: truncate, shrink, or wrap. The contract does not choose one.

## Performance

- Create the text object once per character and rebuild it only when `name`, `status`, `selected`, or `tone` changes. Subscribe to those values, not to positions.
- Update only the transform every frame. Crowded scenes may need overlap avoidance or distance culling (`maxDistance`); measure before adding them.

## Agent guidance

- Use one nameplate per character, with a stable `id` derived from the entity id.
- Use the same player identity and display name as the screen UI entries for that player.
- Derive `selected` from game state so world clicks and screen controls stay in sync.
- Reject `occlusion` and `maxDistance` requests your renderer doesn't implement, rather than ignoring them.
