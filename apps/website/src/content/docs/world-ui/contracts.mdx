Import `FloatingLabel`, `Nameplate`, `HealthBar`, `WorldDescriptor`, `WorldAnchor`, `WorldOffset`, `WorldPoint2D`, `WorldPoint3D`, `WorldDimension`, `WorldPoint`, `WorldPresentation`, and `WorldTone` as types from `@game-ui/world-ui`. Use the dimension parameter (`HealthBar<"3d">`) when an integration knows its world dimension. `WorldDescriptor` is a union discriminated by `kind`.

## Shared configuration

| Field           | Meaning and default                                                                                                                                           |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `id`            | Required scene-unique identity. Content updates preserve the instance and creation time. A new lifetime needs a new instance.                                 |
| `anchor`        | Required entity reference or explicit world position.                                                                                                         |
| `offset`        | Zero by default. World vector before projection, or CSS-pixel vector after projection.                                                                        |
| `tone`          | `default`, `primary`, `success`, `warning`, or `danger`; defaults to `default`. The game chooses meaning and thresholds.                                      |
| `visible`       | Defaults to `true`. Hidden instances still age.                                                                                                               |
| `missingAnchor` | `hide` by default: hide and retry resolution without resetting lifetime. `dispose` permanently ends the instance. Never render a stale last-known position.   |
| `lifetimeMs`    | Omitted = persistent. Finite nonnegative milliseconds since creation on the documented monotonic scene clock. Zero expires immediately. No animation implied. |
| `occlusion`     | Optional capability: `none` (default) or `hide` when blocked under the integration's documented policy.                                                       |
| `maxDistance`   | Optional finite nonnegative camera-to-anchor cutoff in world units. Omitted = no cutoff. Measured after local/world offsets and before screen offsets.        |

Reject invalid configuration at creation/update boundaries. Reject unsupported dimensions or explicitly requested optional capabilities with a useful error so the game can choose a fallback. Never silently ignore such requests. Do not validate descriptors in the frame loop. A renderer may support a documented subset, as the canvas example does.

Required behavior includes content updates, tones, visibility, missing anchors, lifetime, and health normalization for supported anchor/offset forms. Exact typography, sizes, layout, selection decoration, and rendering technique are game choices. Interactions, rich text, assets, overlap avoidance, distance fading, animation, and layout priority are not defined by these contracts.

## Anchors and offsets

```ts
import type { WorldAnchor, WorldOffset } from "@game-ui/world-ui";

const entity: WorldAnchor<"3d"> = {
  kind: "entity",
  dimension: "3d",
  entityId: "pilot-7",
  localOffset: { x: 0, y: 1.8, z: 0 },
};
const position: WorldAnchor<"2d"> = {
  kind: "position",
  dimension: "2d",
  position: { x: 120, y: 64 },
};
const labelGap: WorldOffset<"3d"> = { space: "screen", x: 0, y: -12 };
```

Entity IDs are stable game-owned strings resolved through the entity registry. Native objects and callbacks are not part of the contract. Include generations if IDs are recycled, so a hidden label cannot attach to a different entity accidentally.

Explicit positions are in world space. Entity `localOffset` is applied through the entity's full local-to-world transform, including rotation and scale. A `world` offset is then added in world coordinates; a `screen` offset is added after projection. A descriptor has one additional offset. Combine a local offset with a screen offset for a head attachment with a fixed text gap.

World units, axes, handedness, and camera conventions belong to the integration and must be documented. 2D positions have x/y; 3D also requires z. Coordinates must be finite; unresolvable/non-finite anchors follow the missing-anchor policy. Screen offsets always use **CSS pixels**, +x right and +y down relative to the renderer viewport. Convert to framebuffer pixels using DPR only at the drawing boundary.

Projection failure (behind the camera or outside valid depth) hides a label without disposing its valid anchor. Offscreen clipping and depth visibility differ from a missing entity. For multiple cameras, choose the target viewport and use it consistently for projection, offsets, and hit testing.

## FloatingLabel

See the [FloatingLabel page](/world-ui/floating-label/) for usage, tones, accessibility, performance, and a live example.

Use `kind: "floating-label"` with required plain `text` for a contextual message attached to a place or entity. All shared tones apply; default is ordinary text. Text updates replace content; an empty string draws no text. Strings are never markup.

Use it for a relay label or short-lived health-change notification. Avoid it for viewport notifications (compose text inside Panel) or identity/status (Nameplate). Damage-event handling, trajectories, stacking, and pooling remain game mechanics, not a shipped DamageNumber system.

Text maps to `--game-text` or `--game-{primary,success,warning,danger}-text`; font mapping uses `--game-font-body`. The [live example](/world-ui/canvas/) shows persistent relay text and one-second health-change text.

## Nameplate

See the [Nameplate page](/world-ui/nameplate/) for usage, tones, accessibility, performance, and a live example.

Use `kind: "nameplate"` with required plain `name`, optional plain `status` (omitted = none), and optional `selected` (default = false). Render selection with a visible non-color cue. Do not infer teams, rank, status, or identity from anchor IDs. All shared tones apply to text.

Use it above a character; avoid it for ranked screen data (Scoreboard) or health meters (HealthBar). Share game identity and display names with PlayerList/Scoreboard entries. The canvas example uses `◆` for selection, `Ready`/`Down` status, semantic text colors, and a panel backdrop.

## HealthBar

See the [HealthBar page](/world-ui/health-bar/) for usage, tones, accessibility, performance, and a live example.

Use `kind: "health-bar"` with required `value`, `max`, and human-readable `label`. Minimum is zero. Clamp finite values to `[0, max]`; non-finite values or non-finite/nonpositive maxima display empty. Unknown/indeterminate loading progress is unsupported; screen ProgressBar has its own loading behavior.

Use it for determinate entity health; avoid it for viewport meters or arbitrary task progress. Fill maps to `--game-primary` for default/primary and `--game-{success,warning,danger}` otherwise. The game chooses health thresholds. Feed the same health snapshot into screen ProgressBar rather than maintaining a second authoritative value.

## Accessibility and performance

Canvas geometry has no DOM accessibility semantics. Provide meaningful information and equivalent controls in screen UI; do not rely on color alone. Nameplates need readable text/selection cues; health needs an accessible screen label/value. Do not announce every animation frame or combat event. Sizing, contrast, localization, long-name layout, and input targeting remain integration responsibilities.

Create render objects once and update on content changes. Reuse projection storage; update transforms from the game loop. Resolve theme values at initialization/theme changes. Dispose render objects, transient labels, subscriptions, listeners, and loops on scene shutdown. Profile representative counts before adding pooling or complex culling. The [canvas example](/world-ui/canvas/) documents its supported subset.
